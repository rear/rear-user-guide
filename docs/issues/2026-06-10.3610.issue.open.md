### Describe the ReaR bug in detail

Hello everyone,  
As recommended in
[this](https://github.com/rear/rear/issues/3580#issuecomment-4097577058)
comment, I am opening a new issue here regarding my UEFI boot problem.

Among other things, I use an external hard drive formatted with Ventoy
in UEFI mode (with an EFI partition at the beginning).  
I connect this hard drive periodically to various Proxmox hosts, mount
the Ventoy partition under `/mnt/Disaster-Disk/Ventoy`, and the data
partition under `/mnt/Disaster-Disk/DATA`. Then I manually run
`rear -v mkbackup`.

The rear-config for this always looks on all hosts like this:

    # /etc/rear/local.conf 
    OUTPUT=ISO
    OUTPUT_URL=file:///mnt/Disaster-Disk/Ventoy
    BACKUP=NETFS
    BACKUP_URL=file:///mnt/Disaster-Disk/DATA/rear
    BACKUP_PROG=rsync
    BACKUP_PROG_EXCLUDE+=( ${BACKUP_PROG_EXCLUDE[@]} )
    EXCLUDE_MOUNTPOINTS+=('/mnt/Disaster-Disk/Ventoy' '/mnt/Disaster-Disk/DATA')
    EXCLUDE_RESTORE+=('/srv/backup')

After the backup, I unmount the hard drive again, go to the next host,
and repeat the steps. This way, I always have a bootable offline backup
of my hardware machines.

As an example, I connected the hard drive to the hosts `proxmox-dev` and
`proxmox01` and made a backup on each. The hard drive folder structure
then looks like this:

    user@server:/mnt/Disaster-Disk# tree -L 4

        └── proxmox-dev
            ├── README
            ├── rear-proxmox-dev.iso
            ├── rear-proxmox-dev.log
            └── VERSION

**Important:** `proxmox-dev` is installed in UEFI, so it has an EFI
partition at the beginning and `proxmox01` is Legacy BIOS and therefore
has no EFI partition.

For a disaster recovery test, I now want to connect the hard drive to a
Proxmox VM, boot it up, and perform a test restore of a host (without
data) to see if booting, restoring, etc., works.

And that is exactly what isn’t working. My `DR-Test` VM in Proxmox is
configured with UEFI and looks like this:
