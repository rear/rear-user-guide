The missing kernel modules are coming from the TrendMicro ds\_agent
package. What happened?

The ds\_agent package was removed, but the kernel modules couldn't get
removed as there was still a java component in the process list that
wasn't killed by the removal process. Due to this the cleanup couldn't
do its full job.

How to get rid of these errors?

The cleanest solution is to schedule a reboot, but if that is not
possible in a short notice then use the below procedure.

    #-> rm -f /lib/modules/$(uname -r)/kernel/net/dsa_filter/*
    #-> rmdir /lib/modules/$(uname -r)/kernel/net/dsa_filter

ReaR is tracking the kernel modules found below
`/lib/modules/$(uname -r)/kernel/net/dsa_filter`, therefore, when the
unfound dsa\_filter kernel module links are removed our problem with
reporting a false positive is also gone.
