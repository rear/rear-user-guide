-   Reference to related issue (URL): N/A
-   How was this pull request tested?  
    Validated end-to-end against a live Cohesity 7.4.1 cluster, covering
    both a recovery host that keeps the original hostname/IP and one
    that comes up with different network settings through a Physical
    Server File & Folder recovery.
-   Description of the changes in this pull request:  
    Adds a new BACKUP=COH method for bare-metal recovery of physical
    servers protected by Cohesity DataProtect. Since the Cohesity agent
    cannot pull backups on its own and only accepts connections from the
    cluster, the approach is:
    -   rear mkrescue bundles the installed Cohesity agent, including
        binaries, configuration, runtime state, required libraries and
        commands, and the systemd unit, into the rescue image.
    -   rear recover rebuilds the disk layout, then checks the recovery
        host's hostname/IP against the values stored in the agent
        configuration. If they have changed, the agent identity is reset
        automatically. Files are renamed with a \_rear suffix rather
        than deleted so the agent can register as a new host. If the
        hostname/IP is unchanged, the same reset is offered as an
        optional step. Either way, the original server's registration is
        never touched.
    -   The agent is started so the Cohesity cluster can reach it, and
        rear recover pauses while the actual restore is driven from the
        Cohesity Data Cloud console or REST API. A normal physical
        server recovery is used if the identity was kept, or a Physical
        Server File & Folder recovery if it was reset.

# Cohesity DataProtect with ReaR

Cohesity DataProtect provides policy-based backup and recovery for
supported workloads. A protection policy defines the source, schedule,
retention, and storage target. Backup data is transferred to a Cohesity
cluster and stored as snapshots.

## Backup processing

-   The client or workload is registered as a protection source.
-   A protection job runs according to its assigned policy.
-   Data is read directly from the workload or through a locally
    installed agent.
-   The backup stream is sent to the DataProtect cluster.
-   The cluster deduplicates and compresses the backup data.
-   Encryption protects data in transit and at rest.
-   Snapshots can be configured as immutable, preventing modification or
    deletion during the defined retention period and improving cyber
    resilience.
-   Recovery operations read the required snapshot and restore the
    selected files, volumes, or workload data.

## ReaR integration

For the ReaR workflow, the lightweight Cohesity agent is installed
locally on the Linux client and performs either a file system based or
block based backup.  
The agent can perform source-side deduplication to reduce network
transfer. Backup data is stored on the DataProtect cluster in
deduplicated, compressed, encrypted, and optionally immutable snapshots.
