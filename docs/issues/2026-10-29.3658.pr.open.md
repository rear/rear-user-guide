-   How was this pull request tested?

-   Description of the changes in this pull request:

    Bash does not perform brace expansion on variable values, so the
    `{...}` lists in `FILES_TO_PATCH_PATTERNS` were passed to pathname
    expansion literally, matched nothing, and were dropped by
    `nullglob`. As a result the GRUB files (`grub.conf`, `grub.cfg`,
    `menu.lst`, `device.map`) were excluded from checksum generation and
    from UUID and device name migration. The bug introduced by
    7f61a4f4283e403ba3e44db9ee6bd52bd45d9519.

    Reproduce in a terminal:

        $ mkdir -p boot/grub2
        $ touch boot/grub2/grub.cnf
        $ shopt -s nullglob

        $ for file in [b]oot/grub2/{grub.cnf,grub.conf} ; do echo "$file" ; done
        boot/grub2/grub.cnf <=== expected output, since boot/grub2/grub.cnf exists

        $ GLOB="[b]oot/grub2/{grub.cnf,grub.conf}" ; for file in $GLOB ; do echo "$file" ; done
                          <=== nothing, which is unexpected and indicates the issue

    Replace brace expansion in `FILE_TO_PATCH_PATTERNS` with Bash
    extended globbing, which is implicitly enabled in ReaR.

#### <img src="https://avatars.githubusercontent.com/u/29474856?u=b3637dbf6b72d36a96742d81028e6361add0d388&v=4" width="50">[svlv](https://github.com/svlv) commented at [2026-11-02 15:07](https://github.com/rear/rear/pull/3658#issuecomment-6580543671):

It's better to think about it keeping the following in the head:

    @( … ) | Only one occurrence
    *( … ) | Zero or more occurrences
    +( … ) | One or more occurrences
    ?( … ) | Zero or one occurrences
    !( … ) | Not these occurrences, but anything else

`@(a|b).jpeg` will match `a.jpeg` or `b.jpeg` but not `aa.jpeg` or
`bb.jpeg`. I think this short explanation will be enough
