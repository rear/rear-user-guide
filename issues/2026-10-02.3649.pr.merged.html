#3649 PR merged: swaps: initialize uuid and label as empty strings¶

Labels: bug, fixed / solved / done

svlv opened issue at 2026-10-02 12:51:¶

  • Type: Bug Fix

  • Impact: High (we experienced a system that failed to boot after recovery testing)

  • Reference to related issue (URL):

Description of the changes in this pull request:¶

The global uuid and label variables set in 230_filesystem_layout.sh are still in scope when 240_swaps_layout.sh runs, so a swap partition with no label inherits the label of the last filesystem processed.

Observed layout, where sda3 has no swap label:

lsblk -o name,fstype,label,mountpoint
NAME   FSTYPE LABEL  MOUNTPOINT
sda
├─sda1 vfat          /boot/efi
├─sda2 btrfs  leap16 /var
└─sda3 swap          [SWAP] <= no label for swap

Yet the generated disklayout.conf records a label for it:
swap /dev/sda3 uuid=cc512737-9cb1-4dfd-88a5-301572587ba7 label='leap16'

Unset uuid and label in 230_filesystem_layout.sh to keep them from leaking into other scripts, and explicitly initialize them as empty strings in 240_swaps_layout.sh to guard against the same problem recurring.

How was this pull request tested?¶

Ensured that swap label is empty in disklayout.conf:
swap /dev/sda3 uuid=cc512737-9cb1-4dfd-88a5-301572587ba7 label=
