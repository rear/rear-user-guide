What steps will reproduce the bug?¶

  • Create a rescue image ISO
  • Boot ISO via iDRAC and Virtual Media => kernel panic.
    (- Boot ISO e.g. in a Virtual Box VM with EFI => No issue.)

Workaround, if any¶

Not known.

Additional information¶

The site.confin use is

## Avamar agent installation for your system
#
# export TMPDIR="/var/ReaR"       # Required to be mounted EXEC (!!!)

AVAMAR_ROOTDIR=/usr/local/avamar
AVAMAR_VARDIR=/var/avamar
AVAMAR_ETCDIR=/etc/avamar

# rear staff
ISO_DIR=/var/ReaR
OUTPUT=ISO
BACKUP=AVA00

# Static IP (no DHCP!)
USE_DHCLIENT=
USE_STATIC_NETWORK=yes
USE_RESOLV_CONF=( 'no' )

# Include the loaded kernel modules only
MODULES=( 'all_modules' )

# Set ROOT Password (optional)
SSH_ROOT_PASSWORD='root'

# Clone all current users
CLONE_ALL_USERS_GROUPS=no

# On the host do *NOT* exclude disks for the guests
AUTOEXCLUDE_DISKS=no

# UEFI required - Ref.to. https://access.redhat.com/solutions/7054402
UEFI_BOOTLOADER=/boot/efi/EFI/redhat/grubx64.efi
SECURE_BOOT_BOOTLOADER=/boot/efi/EFI/redhat/shimx64.efi

###
# Avamar specific extensions
COPY_AS_IS_AVA00=( "$AVAMAR_ROOTDIR" "$AVAMAR_VARDIR" "$AVAMAR_ETCDIR" )
COPY_AS_IS_EXCLUDE_AVA00=( "$AVAMAR_VARDIR/*.log" "$AVAMAR_VARDIR/*.dat" "$AVAMAR_VARDIR/clientlogs/*" ) 
PROGS_AVA00=( avtar avregister avagent.bin avscc avupdate detect_firewall avtar.bin )
# End Avamar specific extensions

The AVA00 is a slightly different AVA workflow with us.
