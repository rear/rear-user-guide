jsmeix commented at 2026-08-04 06:44:¶

I have to fix the logic.
Currently it is not right.

Reason:
Currently I misuse empty TRUSTED_OWNERS
in the is_writable_only_by_owner function
as a way out when some special file
is writable not only by its owner
but should be trusted nevertheless.

FWIW:
I had a bad feeling when I implemented that part
but that part was not my primary focus of mind
it was more like "I just need to do something here"
so the outcome was poor - but one (at least I) cannot
focus on more than one thing at a time...

Solution proposal:
My first idea was to introduce a separated

TRUSTED_FILES

config array where the user can specify files that are
trusted "as is" regardless of owner / path / permissions.
I didn't like the "yet another config variable" way
so I evaluated various other ideas but in the end
I always came back to my first idea to be the
most simple and straightforward solution
to allow any special cases.
