jsmeix commented at 2026-09-18 13:05:¶

A side note regarding performance:

I was wondering if my current implementation
in _framework-setup-and-functions.sh

function is_trusted_file () {
    ...
    for trusted_file in "${TRUSTED_FILES[@]}" ; do
        test "$actual_file" = "$trusted_file" && return 0
    done
    return 1
}

...

function source () {
    ...
    if ! is_trusted_file "$source_file" ; then
        # Enforce source file owner is trusted:
        is_trusted_owner "$source_file" || Error "..."
        # Enforce source file is at most writable by its owner:
        is_trusted_write "$source_file" || Error "..."
        # Enforce source file starts with a trusted path:
        is_trusted_path "$source_file" || Error "..."
    fi

is still sufficiently performant
even when there are many files in TRUSTED_FILES
because it always calls is_trusted_file()
which iterates over all files in TRUSTED_FILES.

I tested it with artificial files in TRUSTED_FILES
which are never sourced to ensure all those files
get always needlessly tested in is_trusted_file().

With empty TRUSTED_FILES:

# time usr/sbin/rear -v mkrescue
...

real    0m56.726s
user    0m23.122s
sys     0m37.138s

With 100 artificial files in TRUSTED_FILES:

# time usr/sbin/rear -v mkrescue
...

real    0m56.177s
user    0m22.963s
sys     0m36.676s

With 1000 artificial files in TRUSTED_FILES:

# time usr/sbin/rear -v mkrescue
...

real    0m58.827s
user    0m24.044s
sys     0m38.134s

With 10000 artificial files in TRUSTED_FILES:

# time usr/sbin/rear -v mkrescue
...

real    1m9.900s
user    0m31.514s
sys     0m42.192s

So 100 TRUSTED_FILES are unnoticeable,
1000 TRUSTED_FILES make it about 2 seconds slower,
10000 TRUSTED_FILES make it about 14 seconds slower.

I think my current simple and straightforward implementation
is sufficiently performant up to about 1000 TRUSTED_FILES
but things get noticeably slower if there are thousands
of TRUSTED_FILES which probably won't happen in practice.
