I am not a RHEL user so I cannot help with RHEL specific issues

ReaR version 2.6 is rather old (from more than 6 years ago).
ReaR 2.6 was released in June 2020, see
https://github.com/rear/rear/blob/rear-2.6/doc/rear-release-notes.txt#L195

Some generic boilerplate info:

In general I recommend to try out our latest GitHub master code
because the GitHub master code is the only place where we fix things
and if there are issues it helps when you use exactly the code
where we could fix things.

See the "QUICK START GUIDE" and "INSTALLATION" parts on
https://github.com/rear/rear

Additionally / alternatively see the section
"Testing current ReaR upstream GitHub master code" in
https://en.opensuse.org/SDB:Disaster_Recovery
how you can try out our current ReaR GitHub master code
without conflicts with your already installed ReaR version.

In general we at ReaR upstream do not support older ReaR versions.
We at ReaR upstream do not plain reject issues with older ReaR versions
(e.g. we may answer easy to solve questions also for older ReaR versions)
but we do not spend much time on issues with older ReaR versions because
we do not (and cannot) fix issues in released ReaR versions.
Issues in released ReaR versions are not fixed by us (by ReaR upstream).
Issues in released ReaR versions that got fixed in current ReaR upstream
GitHub master code might be fixed (if the fix can be backported with
reasonable effort) by the Linux distributor wherefrom you got ReaR.

Our latest release ReaR 2.9
and our current ReaR upstream GitHub master code
still support RHEL 8, see
https://github.com/rear/rear/blob/rear-2.9/doc/rear-release-notes.txt#L126
and still the same in our current
https://github.com/rear/rear/blob/master/doc/rear-release-notes.txt#L126

A side note regarding

export TMPDIR="/backup/rear/tmp"

in a ReaR user config file like etc/rear/local.conf
see our current ReaR config documentation in
usr/share/rear/conf/default.conf
the comment about TMPDIR
therein in particular the part about
how to properly set TMPDIR in general
for any program in a POSIX compliant way,
i.e. export TMPDIR before running the program
and specifically for 'rear':

To have a specific working area directory prefix
for Relax-and-Recover call
    export TMPDIR="/prefix/for/rear/working/directory"
before calling 'rear'
(/prefix/for/rear/working/directory must already exist).

https://github.com/rear/rear/blob/master/usr/share/rear/conf/default.conf#L160C1-L162C81

Another side note regarding

NETWORKING=yes
HOSTNAME=su01005000
IPADDR=10.71.40.82
NETMASK=255.255.254.0
GATEWAY=10.71.40.1
DNS=(10.71.181.13 10.46.181.13 10.71.181.12)

Only HOSTNAME is listed in usr/share/rear/conf/default.conf
but none of the other variables is listed there
so I assume setting the other variables may not do
what you expect.
In particular DNS and NETWORKING variables do not appear
in ReaR scripts.
And IPADDR NETMASK GATEWAY get set from the kernel command line
options ip nm gw by the ReaR recovery system startup script
usr/share/rear/skel/default/etc/scripts/system-setup.d/20-check-boot-options.sh
see in usr/share/rear/conf/default.conf
the comment about
"Relax-and-Recover ... special kernel command line parameters"
https://github.com/rear/rear/blob/master/usr/share/rear/conf/default.conf#L204

SamiSZZzz commented at 2026-09-01 08:20:¶

We had once similar issue. Problem seemed to be then in too large initrd file. Backup creation worked, but booting from iso image failed to kernel panic.

With original config, initrd was close to 1Gb and boot failed:
Created initrd.cgz with gzip default compression (993456331 bytes) in 50 seconds

But when added to /etc/rear/local.conf line:
REAR_INITRD_COMPRESSION="lzma"

Initrd size decreased to ~700M:
Created initrd.xz with xz lzma compression (679592202 bytes) in 304 seconds

And with that size, restore from back seems to work. Maybe you can try if same will help for you.

FIRMWARE_FILES
to get only firmware included which is actually needed.
